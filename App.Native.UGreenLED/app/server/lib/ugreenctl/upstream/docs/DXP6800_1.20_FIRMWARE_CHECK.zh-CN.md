# DXP6800 Plus：1.20.0.0142 固件逆向与接入

## 2026-10-27 WOL / RTC 接线补齐

本次重新核对下述同一原厂镜像：`hwmonitor.sh` 将 Plus 路由到 `hwmonitor-480t`，
其二进制包含 eth0/eth1 的 wol g/d 命令与 `power.wake_on`。
新增独立 Plus WOL 映射并接入既有 WOL/RTC 实现；此前“WOL 未核对、不开放”的
结论由本次核对更新。飞牛等系统的 enp*/eno* 名称由上游物理 PCI 网卡解析器处理，
两网口拓扑、Magic Packet 支持检查和写后回读保持有效。RTC 使用 Linux wakealarm，
不依赖网卡名称。上述均保留实验性写入确认，不声明关机唤醒已通过实机验证。

## 2026-10-16 原厂预设追查与用户实机反馈

用户反馈“实机验证过了”。这是用户报告的验证结果；未提供具体硬件修订、测试日志和逐项范围。
保留现有写入保护，不据此推断原厂曲线数值已验证。

本次继续检查同一 SHA-256 的原厂镜像，不质疑其原厂来源。发现以下读取链路：

- `hwmonitor-480t:getDevModel` 的 `0x98e3..0x991a` 比较 DMI 前七字节
  `DXP6800`，设置 `HWCONFIG=/etc/default/dxp6800.conf`，Plus 命中此分支。
- `load_hw_config` 在 `0x4eba..0x4efb` 检查配置是否存在；缺失时选择
  `/etc/hwmon.conf`。`0x4f00..0x4f31` 读取 `/etc/fan.conf` 和选定硬件配置。
  具体温度/PWM 点通过 `getDataByConf` 载入 `pwmSlope`；该结构位于 BSS，不能将零初始化当作原厂预设。
- 模式 1（静音）在 `0x510d` 分支，对 DXP6800 不采用 DX4/DXP2800 的温度加 5°C 分支。
  `0x5252..0x52f6` 把系统与 CPU 的 start/mid/full PWM 点分别乘 90 再整数除 100；
  max 点不在这六次改写范围内。这证明相对缩放，不证明基准 PWM 数值。
- `ugreen.bz2` 实际为 tar。已解析其中控制中心 UPK 的长度字段、gzip tar 和内层 xz tar，
  并恢复 `ctl_serv` 的 Go 函数表。`fan.GetSystemConfig` 读取 `/etc/default/<去空格小写型号>.conf`；
  在本次恢复的 `queryFanCategory` 调用处仅精确 DXP4800 使用此函数，不能据此宣称 Plus 改用了另一份配置。
- 原厂前端的默认自定义折线是 0..80°C、20..100% 线性插值；它是编辑器的缺省值，
  **不是 Plus 原厂智能预设**，不移植为 stock preset。

检查范围：外层 kernel/fw/apt/oem SquashFS、zstd/cpio 启动镜像、
18 个 V1 内层应用包的配置和脚本。两个 V2 包（媒体服务、控制中心索引）未拆解，
不声称已经穷尽全部文件内容。已检查范围未找到 `dxp6800.conf`、`dxp6800plus.conf`、`hwmon.conf`。
镜像 `os-release` 声明 `DEPEND_FW_VERSION=1.19.0.0000`，入口脚本调用 `ugpt upgrade`；
配置可能来自已安装基础系统，这只是结合包结构的推断，不能据此否认它是原厂镜像。

分析产物保留于 `firmware-inbox/work/dxp6800plus/`：`curve-annotated.txt`、
`ctl-fan-fast.txt`、`scan_presets.py`、`preset-scan.json` 和 `ctlmgr-fields/`。
当前结论：Plus 的本版原厂阈值和基准 PWM 仍为 unknown；未以旧 Pro 或前端自定义默认值代替。
本轮只更新证据文档并同步到 LLLED_FPK 内置源码，没有修改控制参数或重新构建。

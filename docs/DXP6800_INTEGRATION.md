# DXP6800 BIOS / fan integration

The exact DMI product `DXP6800` now uses upstream's independent `dxp6800.so`.
The upstream evidence and implementation are in
`E:/工作台/UGREEN-NAS-Hardware/docs/DXP6800_SUPPORT.zh-CN.md`.
The application only adapts the CLI, API, telemetry and UI.

Capabilities: CPU PWM, paired system PWM, three fan tachometers, and AC recovery
on/off/restore. Experimental confirmation, PWM 40..255, controller identity,
ownership checks, locking and readback remain enforced upstream. Custom software curves and the user-selected `stock-6800` compatibility preset
are available. The preset uses DXP6800 Pro parameters and is labeled accordingly;
the original DXP6800 factory curve remains unknown.
No target-device hardware write or physical power-cycle validation was performed.

## Local upstream artifact

`scripts/hardware-release.json` pins a **immutable, committed preview** extension archive in
`UGREEN-NAS-Hardware/artifacts/Almighty/2026-10-28-dxp6800-wake-curve-local`.
The exact artifact commit is pinned in the lock; the directory name records its original local-build provenance.
The prior immutable artifact is recorded under `base`. Only `dxp6800.so` and
`ugreenctl-fand` differ among executable payloads. LED CLI bytes are unchanged.
The extension embeds the relevant upstream source snapshot and its SHA-256 map;
the base Git revision does not claim that the extension is a committed release.

Reproduction:

1. Build upstream `build-dxp6800` with the Linux CMake toolchain and run CTest
   (on Windows use the repository's external Zig toolchain and QEMU test runner).
2. Compose the extension using upstream `prepare-llled-dxp6800.py` with the existing wake archive as BASE, its pinned hash as BASE_SHA, and `2026-10-28-dxp6800-wake-curve-local` as OUT. See the reproduction script alongside that archive.
3. Verify the archive, manifest and SHA256SUMS against the LLLED lock. Source or
   compiler changes produce new hashes and require an explicit lock update.
4. Run LLLED `python scripts/build_ugreenctl.py` to verify/import all ten plugins.
5. Run BIOS control/API/fan-curve API tests and `web-ui` typecheck/build.

Both FPK entry points require the independent plugin and continue validating all
payloads against the pinned manifest. Packaging remains a separate user action;
this integration does not create an FPK, push a branch/tag or publish a Release.

## Pro-parameter compatibility curve (2026-10-28)

At the user's request, `stock-6800` now adopts the DXP6800 Pro policy (the Plus
compatibility preset already uses the same policy). CPU thresholds are
25/38/55/75/90 C, HDD 30/35/43/48/55 C, NVMe 45/50/60/65/70 C. System PWM is
64/130/210/230 and CPU PWM is 80/130/210/230; CPU floor is 65 C / 125 to 90 C / 220.
Exact DMI, hardware mapping, write guards, minimum PWM and missing-sensor failsafe
are retained. The UI labels both DXP6800 and Plus presets as using Pro parameters.
The current extension can be reproduced with `reproduce.py` alongside its pinned
archive. Both local application workspaces are updated; existing FPKs were not
rebuilt by this curve change. Physical thermal response remains unvalidated.

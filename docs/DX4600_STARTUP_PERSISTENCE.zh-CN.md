# DX4600 来电策略恢复

现象：设置来电开机成功，关机后再启动或重启，读到的策略回到关闭。

代码核对：上游 `E:\工作台\UGREEN-NAS-Hardware` 的 `models/dx4600.c`
调用 `power/it8613_power.c`，按固件证据写入 IT8613 的 `0xf2/0xf4`
并回读验证。此操作不修改 BIOS NVRAM，不能由一次写入成功推断跨重启持久化。
证据见上游 `docs/DX4600_REVERSE_ENGINEERING.zh-CN.md` 第 4 节。
本次未改动上游硬件实现。

应用修复：

- 用户在 API 中确认设置后，只有上游写入成功才把精确 DMI 和策略作为一条
  `bios.startup_selection` 配置保存到应用持久目录的 `settings.conf`。
- 服务启动时，以及停止温控服务后，再调用带 `--force --apply` 的上游
  `ugreenctl power startup set` 恢复选择。硬件锁、身份检查、回读仍由上游负责。
- 没有保存过选择时不写入默认值；配置属于不同精确机型时不恢复；无效策略不写入。
- 保存失败由 API 返回错误；恢复失败记录 `bios.startup_restore_failed`，不伪造硬件状态。

升级后需要重新选择并保存一次来电策略，旧版没有保存过的选择无法自动推断。
应用须随系统启动。此修复属于软件恢复，不保证 BIOS 或其他程序在服务停止后
继续覆盖寄存器的情况。2026-09-19 用户确认 DX4600 断电恢复已实测通过；
该确认针对当前应用与上游组合，不改变软件恢复的实现性质。

回归测试：`tests/test_startup_persistence.sh` 覆盖新进程恢复 on/off/last、
未设置不写入、精确机型隔离、硬件失败不覆盖配置、无效配置和保存失败；
`tests/test_bios_api.sh` 检查 API 保存行为。

2026-09-19 用户进一步确认 DX4600 的断电恢复、WOL、风扇控制均实测通过。
本记录据此将断电恢复列为用户实测通过；没有逐策略测试记录时，不补写
on/off/last 各模式、循环次数等未提供的细节。后续修改应回归已验证功能。
